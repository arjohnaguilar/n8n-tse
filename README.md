

# 🔐 2FA / Login Support SOP (Intent-Based – Growsari TSE)

This SOP handles 2FA, login, and password-related concerns using an **intent-first approach**.

---

# 🧭 1. Core Principle

Do **NOT** require perfect formatting.

Instead:

* Identify if issue is **login or 2FA related**
* Identify the **application or website involved**
* Extract available details
* Ask minimal follow-ups only when needed

---

# 🌐 2. Supported Applications / Websites

Identify which system the user is referring to:

## 📱 Apps

* Shipper App
* PSP App

## 🌍 Web Platforms

* [https://logistic.growsari.com](https://logistic.growsari.com)
* [https://admin.growsari.com](https://admin.growsari.com)

👉 Always try to map the user issue to one of these systems first.

---

# 🧠 3. Intent Detection Rule

If the user mentions:

* 2FA not working
* Login failed
* Cannot access account
* OTP issue
* Authenticator issue
* Password issue / forgot password

👉 Treat as a **VALID SUPPORT REQUEST**

---

# 🔍 4. Information Extraction (Best Effort)

Try to identify:

* Application / website (Shipper App, PSP App, logistic, admin)
* Store / Account ID
* Name
* Mobile number
* Issue type (login / 2FA / password)

⚠️ If missing:

* Do **NOT** block processing
* Continue with available info

---

# 🧭 5. Support Flow (MANDATORY)

## ✅ STEP 1: Confirm Application + Issue

> “Which application are you having an issue with (Shipper App, PSP App, Logistic, or Admin), and is this a login or 2FA issue?”

---

## 🔍 STEP 2: Basic Checks

Ask:

* Have you rechecked your password?
* Are you using the correct credentials?
* Did you recently change your password?
* Can you receive OTP via email or phone?

---

## 🔄 STEP 3: Retry Login

* Ask user to retry login
* Confirm if issue persists

---

## 🎯 STEP 4: Decide Outcome

### ✔ If RESOLVED:

* Confirm resolution
* End flow

### ❌ If NOT RESOLVED:

* Proceed to evaluation

---

# 🔐 6. 2FA Reset Conditions

ONLY proceed if:

* Password is confirmed correct
* Basic troubleshooting failed
* Issue is clearly 2FA-related
* No suspicious activity detected

---

# ⚙️ 7. 2FA Reset Execution

If approved:

1. Locate account
2. Remove existing 2FA binding
3. Reset authentication setup
4. Trigger re-enrollment
5. Log action

---

# ❗ 8. Password-Related Issues (STRICT RULE)

🚫 **ONLY TSE can reset passwords**

If user reports:

* Forgot password
* Cannot remember password
* Password reset request
* Account locked due to password

👉 Action:

* DO NOT troubleshoot further
* DO NOT attempt reset
* Immediately escalate to TSE

---

# 🚨 9. Escalation Rules (TSE HANDOFF)

Escalate if:

* Any password-related issue
* Identity cannot be verified
* Account not found
* Suspicious activity
* Issue persists after troubleshooting

👉 Escalation Path:

* Contact **TSE in POST Tech GC**
* OR file a **ticket in the ticketing system**

---

# 📢 10. Communication Rules

* Start with confirmation
* Keep questions minimal
* Avoid over-collecting data
* Guide step-by-step

---

# 🧠 11. Support Behavior Rules

* Prioritize intent over format
* Never reject incomplete reports
* Extract what is available
* Always resolve or escalate fast
